Задание

Одно на всех: свой цифровой рудник

Треков и номинаций не было. Команда начинала с Замысла — первого раздела SUBMISSION.md, который пишется до кода: какое предприятие или его часть, кто пользуется двойником, какое решение он помогает принять и почему выбрано именно это. По одинаковому заданию агенты ИИ строят одинаковый рудник; разные двойники получаются у разных людей. Пример рудника в платформе служил только образцом того, как всё устроено; оценивалось то, что сделала Команда.

Ход конкурса

Три шага до Финала

  1. 1

    Регистрация

    Команды регистрировались через форму. Каждый Участник получал приглашение в приватный Репозиторий команды с полной копией OpenEgiz.

  2. 2

    Постройка на OpenEgiz

    Сначала Замысел, затем код. Двойники — в Eclipse Ditto, данные передаются через платформу, интерфейс получает их из неё. Изменять можно было любые части, включая ядро. Допускались любые инструменты, в том числе ИИ.

  3. 3

    Сдача до 25 октября

    В ветке main: README.md, SUBMISSION.md и presentation.pdf. В 23:59 репозитории заморожены и стали публичными.

Главное техническое требование. Решение должно было запускаться по README без ручного вмешательства в Окружении судьи — чистой виртуальной машине Ubuntu с Docker.

Как оценивали

Судили модели ИИ, а не люди

Несколько моделей ИИ, в том числе OpenAI и Anthropic. Рубрика — в Положении. Контрольная сумма пайплайна опубликована 27 октября, после Заморозки, с опозданием против п. 8.5 (Discussion #3). Промпты Судей, код пайплайна, отчёты и оценки опубликованы после Отборочного этапа.

Сборщик

Запускал каждое Решение по README в чистой виртуальной машине и составлял Отчёт сборки

Точка отсчёта по Положению — Типовое Решение: то, что агенты ИИ делают из Шаблона по одной фразе, без Замысла и правок. Типовое Решение не опубликовано; Судьи определяли уровни по описаниям уровней Рубрики.

Решение, не запустившееся по README или построенное не на OpenEgiz, получало не более 40 баллов и не могло стать Победителем. Подробнее — в Положении.
