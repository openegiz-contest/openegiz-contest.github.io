Окружение судьи

Каждое Решение поднимается в своей свежей виртуальной машине: из одного и того же базового образа, а после оценки машина уничтожается. В ней нет ничего от других Решений и ни одного ключа или токена Организатора. Здесь описано, что это за машина, чтобы вы могли повторить её у себя и проверить README до Заморозки.

Английская версия с подробностями — docs/judge-environment.md в репозитории пайплайна ИИ-жюри; он публикуется до Заморозки.

Машина
Архитектура amd64 (x86-64), виртуальная машина KVM
Процессор 8 vCPU
Память 16 ГиБ
Диск 60 ГБ, на старте свободно около 55 ГБ
ОС Ubuntu 24.04.5 LTS, официальный cloud image (noble-server-cloudimg-amd64.img, сборка 20260926), ядро 6.8
Docker Docker Engine 29.1.3, Docker Compose 2.40.3, Buildx 0.30.1 — всё из архива Ubuntu
Предустановлено только то, что есть в cloud image (git, curl, python3 и т. п.), плюс Docker. make нет: ставьте нужное в README (sudo apt install -y make)
Пользователь judge, в группе docker, sudo без пароля

Автоматические обновления apt выключены, чтобы они не держали блокировку apt, пока ваш README сам вызывает apt. Больше в образе ничего не менялось.

Повтор шага. Упавший шаг README повторяется один раз без изменений, засчитывается последняя попытка (Положение, 6.4). Шаг, которому понадобилось больше попыток или который прошёл только после изменения команды, считается упавшим.

Сеть

  • Интернет есть. README может скачивать что угодно: образы, пакеты, датасеты, модели.
  • Локального нет. Машина не видит хост, локальную сеть, другие виртуальные машины, адреса VPN и Tailscale, link-local и облачные метаданные, частные диапазоны (10/8, 172.16/12, 192.168/16, 100.64/10, 127/8, 169.254/16). IPv6 выключен.
  • Docker Hub идёт через прозрачный кэш на хосте: те же образы, те же digest; если кэш недоступен, Docker тянет образы с Docker Hub напрямую. Остальные реестры (ghcr.io, quay.io и др.) — напрямую. Сборки образов не кэшируются: каждый docker build идёт с нуля.
  • Порты, которые публикует ваш стек, доступны только изнутри машины и из браузера Судей (ниже). Привязка к 127.0.0.1, как в самой платформе, подходит.

Как запускается Решение

Загружается свежая машина (около 10 секунд). Сборщик — агент ИИ, который работает вне машины, — заходит по ssh пользователем judge и выполняет ваш README слово в слово, начиная с чистого git clone репозитория на коммите Заморозки.

Лимит времени на запуск (Положение, 6.4) — сейчас 75 минут на всю работу Сборщика: выполнить README, затем проверить ваши Модули и условие «построено на OpenEgiz». Рассчитывайте, что ваш README поднимает стек с большим запасом: сама платформа поднимается за 2–5 минут (см. ниже). Если время вышло, Сборщика останавливают, и поднялось ли Решение, решают автоматические проверки: работают ли контейнеры и здоровы ли они в этот момент. Значение — настройка пайплайна, оно публикуется вместе с ним.

Время самой платформы OpenEgiz в этом окружении (замеры 5 октября 2026, README Шаблона слово в слово):

Шаг Кэш Docker Hub пустой Кэш уже заполнен
Загрузка машины до ssh 9–10 с 10–14 с
sudo apt install -y make 3 с 4–6 с
make up (15 образов, 5,1 ГБ) 196 с 79–85 с
make example-mine 21 с 30–39 с

Три машины, одновременно выполняющие make up, укладывались в 183–223 секунды каждая.

Как Судьи видят ваш интерфейс

Судьи сами открывают ваш интерфейс в браузере Chromium. Браузер работает вне машины, но каждое его соединение открывается внутри вашей машины. Поэтому он видит ровно то, что увидел бы пользователь, сидящий за этой машиной, с той же сетью, что у вашего Решения:

  • Для своих сервисов используйте http://localhost:ПОРТ (или 127.0.0.1), порт любой. Панель Grafana на localhost:3000, которая загружает Unity-сцену с localhost:8090, работает так же, как у вас на ноутбуке.
  • У браузера та же сетевая политика, что у Решения. Интернет работает: страница может грузить скрипты, стили, шрифты, тайлы карт с CDN и обращаться к внешним API. Чего не видит машина (хост, локальная сеть, VPN, частные диапазоны), того не видит и браузер. Внешние адреса самой машины и [::1] из браузера недоступны — используйте localhost.
  • Если CDN или внешний API во время оценки не работает, страница сломается у Судей так же, как у любого пользователя. Надёжнее отдавать важные файлы из своего стека.
  • WebGL работает, включая сцены Unity. Без видеокарты Chrome рисует его программно — это медленнее. Большие сцены скачиваются из вашей машины в браузер Судей: делайте их настолько маленькими, насколько разумно.

Как повторить у себя

Подойдёт любая машина или виртуальная машина Ubuntu 24.04 amd64 с 8 CPU, 16 ГБ памяти и 60 ГБ диска, Docker Engine 29.1 и Compose 2.40 и без лишнего софта. Ближе всего — виртуальная машина из того же cloud image:

# Ubuntu 24.04 с 8 vCPU / 16 ГБ / 60 ГБ, например через multipass:
multipass launch 24.04 --cpus 8 --memory 16G --disk 60G --name judge
multipass shell judge
# внутри:
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2 docker-buildx
sudo usermod -aG docker "$USER" && newgrp docker
docker version    # Server: 29.1.x

Затем склонируйте свой репозиторий заново и выполните свой README слово в слово. Если что-то работает только потому, что уже есть на вашем ноутбуке (утилита, переменная окружения, скачанный образ, файл вне репозитория), здесь оно упадёт.
